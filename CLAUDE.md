# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

cardioEMI solves the cell-by-cell (EMI) electrodiffusion model on cardiac geometries with FEniCSx + multiphenicsx. Each cell volume tag corresponds to a separate FEM space; membrane facets between tags carry coupling/ionic-model jump conditions.

## Running

```
mpirun -n 8 python3 -u main.py input.yml
```

Inputs (YAML) reference an XDMF mesh with `cell_tags`/`facet_tags` and a pickle dictionary (`tags_dictionary_file`) mapping each volume tag to the set of facet tags it touches. `ECS_TAG` defaults to `min(volume tags)`. See `input*.yml` for examples (electrode terms, ionic models, sigma fields can be Python strings evaluated against `ufl`/`np`/`x`).

`random_rhs: True` switches on benchmark mode: the matrix is assembled from the physics as usual, but each timestep solves against a freshly drawn random vector instead of the ionic-model RHS (no ODE evaluation, no solution unpacking unless `save_output`). `random_rhs_seed` (default 0) is offset per rank. Used for weak-scaling/solver studies — see `input_plus_weak_scaling.yml`.

Single-test entry points are standalone scripts (`test_*.py` at repo root) — run directly with `python3 test_partition_verify.py` etc. There is no pytest harness.

## Architecture

Solver pipeline lives in `main.py`; supporting modules are flat at the repo root:

- `utils.py` — YAML input parsing, `read_input_field` (numbers / UFL expression strings / `Function`), output paths.
- `ionic_model.py` — abstract `Ionic_model` + factory; concrete: Null, Passive/Ohmic, Hodgkin–Huxley, AP. Selected per-membrane-pair via `ionic_model.intra_intra` / `intra_extra` in YAML.
- `native_assembly.py` — assembles DOLFINx block forms directly to COO with global indices, bypassing PETSc, for the Ginkgo backend (uses un-accumulated ghost values matching Ginkgo `assembly_mode::communicate`).
- `matis_assembly.py` — assembles to PETSc `MATIS` format for the `PCBDDC` preconditioner (per-rank local SeqAIJ + `ISLocalToGlobalMapping`).
- `mesh_partition.py` — METIS-based component partitioner (`partition_mode: component` in YAML). Maps colored mesh cells back to original (uncolored) component tags via KD-tree centroid matching, partitions components, then DOLFINx custom partitioner returns `AdjacencyList_int32` with owner + ghost destinations derived from cell-facet connectivity. Required when running on colored meshes (which use only ~4 tags to dodge MPI's 2048-communicator limit) but you still want ECS+cell pairs co-located. `component_granularity` (YAML, default `component`) picks the partitioning unit: `component` merges each (ECS chunk, cell) tag pair into one unit and lets METIS balance units across ranks by weighted size (can leave some ranks empty). `tag` instead gives every individual tag its own unit and skips METIS entirely, assigning tags to ranks 1:1 — MPI rank count must equal the number of tags exactly, or it raises (matches a domain-decomposition convergence theory, such as BDDC, stated per volume tag; METIS's size-balancing would otherwise merge small tags onto one rank and leave others empty, defeating the point).
  `partition_mode: cube` is the weak-scaling variant: one subdomain per cell and one for the ECS remainder of the same box (2·nx·ny·nz subdomains, rank count must divide that). Lattice geometry comes from the `<plus|cell>_<nx>x<ny>x<nz>_n<n>_L<L>[_p<pad>][_a<ax>]` filename, or from `cube_partition: {nx, ny, nz, n, L, pad, ax}` in the YAML. Boxes are `ax·L` long in x (`ax` defaults to 1, which is the only value the cubic `plus` meshes use). Verify with `mpirun -n <2·boxes> python3 test_cube_partition.py <mesh.xdmf>`.
- `geometry/generate_weak_scaling_mesh.py` + `geometry/cell_box_gmsh.py` — the weak-scaling lattice: Nx×Ny×Nz identical boxes of `ax·L × L × L`, one cell each, checkerboard 2-coloring (ECS→0, ICS→1/2). `--n` is elements per L. Two `--shape`s:
  - `cell` (default, `--ax 4`) — **unstructured tetrahedra from gmsh + OpenCASCADE**. A body cylinder along x spanning the whole box (both x-face cross-sections are full-radius discs, so cells butt end to end), plus two connectors that cross the whole box — one y=0→y=L, one z=0→z=L — each an exact circular disc **extruded along an oblique vector**, which is what keeps the interface round while the connector leans in x.
  - `plus` (`--ax 1`, `n` a multiple of 4) — the original structured Kuhn-split voxel grid, exactly 50/50 ICS/ECS.
  **The lattice is shifted and wrapped, not mirrored.** Every cell is a pure *translate* of every other, so all connectors lean the same way and the tissue has one fibre direction. (An earlier mirrored variant tiled fine but flipped the lean on alternate cells, destroying that.) A connector entering `y=0` at `lat_x` leaves `y=L` at `lat_x + s`, so the box above must sit `s` further along x. The offset is taken **modulo the box** — box (I,J,K) sits at `x = I·Lx + ((J+K) mod slabs)·s` — so rows **zig-zag** between `slabs` x-positions and the block overhangs by only `(slabs−1)·s` instead of the `(ny+nz−2)·s` a diagonal lattice would need: a cell that would walk past the end folds back into the padding. With the default `--slabs 2`, `s = Lx/2` puts a connector's two interfaces at `Lx/4` and `3Lx/4` — as far towards the cell's two ends as one straight connector can reach — and the overhang is half a box.
  **The wrap forces a different 2-colouring.** When `(J+K) mod slabs` rolls over, a y connector lands in box `(I+1,J+1,K)` rather than `(I,J+1,K)`, and those two have the *same* `(I+J+K)` parity — the plain checkerboard would give two touching cells the same tag. Colour by the **unwrapped** index instead: `(I − (J+K)//slabs + J + K) % 2`, the index the cell would have had on the diagonal lattice.
  **How the shifted faces still mate:** the rectangular box is still a fundamental domain, but its `+y` face is the `−y` face translated by `(s,L,0)`, which runs off the end in x. Split the box into `m = Lx/s` slabs along x (`--slabs`, default `ax`, giving `s = L` and a 45° lean) and the correspondence is exact slab by slab: slab `k` of `−y` maps to slab `k+1` of `+y`, the last wrapping under an extra `−a1`. gmsh then gets `m` pure translations per face pair. A connector disc must sit inside one slab (checked) or its face piece has no image.
  **Verification:** `free_surface()` sums the block's expected free surface box by box from the actual x overlaps (each y/z face is shared with *two* boxes, and what they leave uncovered is the zig-zag step), and `_verify_conforming` compares it against the welded boundary area. Worth keeping honest — a cuboid formula silently under-predicts and would mask a genuine welding failure. Separately, connected-components on the ICS tets must return exactly `nx·ny·nz` cells: fewer means the colouring let two touching cells share a tag, more means a cell was split.
  **OCC traps:** a multi-tool `occ.fuse` whose tools overlap each other *silently returns just the object* — the connectors vanish with no error (the ICS volume comes out exactly the body's). Fuse one tool at a time.
  `--pad` counts **element layers of `L/n`** for both shapes. For `cell` it is a true boundary layer: every boundary node is offset along its area-weighted normal and the shell is filled with prisms split into three tets each — conforming by construction (it shares the block's boundary triangulation), and built from the *surface* so there are no gaps at edges or corners. Cost scales with surface, not volume: ~+37% tets for 2 layers on a 2×2×2 block, versus 27× for the whole-box padding it replaces. Do **not** use the tempting square mitre (offset `step` along each distinct face normal): it moves a convex-corner node `step` tangentially, which is exactly the node spacing, so the corner lands on its neighbour's offset and the prisms between them collapse — averaged normals keep the field smooth across the edge instead. `pad_boundary_layers` asserts every tet came out positive. `--dry-run` prints ASCII slices of the analytic solid (`cell_contains`) and the ICS fraction — which is also the `partition_mode: cube` load balance — without meshing. `cube_subdomain_ids` bins y and z first, then subtracts `(J+K)·s` before binning x.
- `geometry/` — mesh generation/conversion. `convert_pts_elem.py … --colored` applies graph coloring to reduce volume tags (large assembly speedup). `tag_facets.py` produces the `(mesh.xdmf, tags.pickle)` pair from a volume-tagged mesh.
- `dolfinx-ginkgo/` — optional GPU solver backend (CUDA/HIP/SYCL/OpenMP). `main.py` tries multiple import paths so it works both in the dev Docker image (`build/_cpp*.so`) and in the Apptainer image (`/usr/local/dolfinx_ginkgo/`). Krylov: CG/FCG/GMRES/BiCGSTAB/CGS; preconditioners: Jacobi, BJ, ILU, IC, ISAI, AMG. Build via `dolfinx-ginkgo/Dockerfile` or the BDDC variant.
- `viz/` — Flask server (`server.py`) + Three.js frontend for browsing meshes, configuring runs, launching simulations, and playing back results / exporting video. `viz/cluster.py` drives remote HPC runs on any cluster registered in `viz/clusters.yml` (currently Karolina and Vega); routes live under `/api/cluster/<id>/...` and `/api/clusters` (registry CRUD, editable via the ⚙ "Clusters" dialog next to the run-target dropdown). All ssh/scp/rsync goes through OpenSSH ControlMaster multiplexing (`~/.ssh/cardioemi-cm/`), so a 2FA/OTP cluster (Vega, `needs_otp: true`) is authenticated exactly once via the webapp's Connect button — the server drives ssh under a pty (pexpect, must be pip-installed locally) and forwards the OTP prompt to a modal; the master then persists until reboot/`-O exit`. Non-interactive calls always use `BatchMode=yes` (fail fast, never hang on a prompt). The per-cluster Install button creates the remote dir layout, rsyncs the code, and provisions container SIFs (local `containers/` copy → streamed from another cluster that has it → `apptainer pull` for the plain DOLFINx image). Per-cluster SLURM defaults, env quirks (e.g. Karolina's `unset SINGULARITY_BINDPATH ...`, `FI_PROVIDER=tcp`), and srun pinning flags all come from `clusters.yml`. `scripts/sync_to_cluster.sh <id>` rsyncs code to any registered cluster (`sync_to_karolina.sh` is a back-compat wrapper).
  With a cluster target, the mesh panel is a checklist (`viz/js/app-mesh-batch.js`): ticked meshes form a batch, clicking a name focuses it (viewer, sliders, stimulus box). Each ticked mesh gets a row of rank counts (empty = the shared mode: `= subdomains`, `÷ k`, or custom; comma lists submit one job per count) and an optional walltime, and is checked against the same rank rules `main.py` enforces (cube: ranks divide 2·nx·ny·nz; per-tag: ranks = tags). Submit goes to `/api/cluster/<id>/submit-batch` → `Cluster.submit_batch`: one scp + one ssh for all jobs. Each job runs with its own run folder as cwd, because Ginkgo's BDDC writes `IF_<rank>.txt` to cwd and concurrent jobs in a shared cwd overwrite each other's interface files. So `main.py` resolves its own imports and JIT cache relative to `__file__`, and every job's YAML is the focused mesh's config with `mesh_file`/`tags_dictionary_file`/`out_name` swapped for absolute `/home/fenics/...` paths, `cube_partition`/`original_mesh_file` dropped, and `v_init` rebuilt per mesh from the batch-wide stimulus box (`stimulusBoxFor` in `app-ui.js`). Each end of each axis is either ticked ("min"/"max": that mesh's own bound) or an absolute slider position, clipped to the mesh. A row whose box misses its mesh blocks submission. Don't map the box as fractions of the bounds: for a weak-scaling series that shrinks "the first cell column" to a sliver on the small meshes. Nodes = fewest at ≤ "Max tasks/node", launched with exact `srun -n`. Scar is refused unless the batch is just the focused mesh. The optional folder path files every run of the batch in the Runs browser.
  **Remote mesh preview:** selecting a mesh that only exists on a cluster shows its membranes, not a bounding box. `viz/scripts/mesh_preview.py` runs next to the mesh, inside the DOLFINx SIF; it is sent inline, so it doesn't depend on synced code. It keeps the tag>0 facets plus only the vertices they use. Above `max_facets` (1M) it coarsens them by grid vertex clustering, with the cell size taken from the membrane area. The full-mesh bounds go in its metadata. The preview is cached in `<remote>/viz/previews/<mesh>/` (reused while newer than the `.h5` and built for the same budget) and in `viz/data/_preview/<mesh>/`, kept separate from real conversions because its vertex ids are compacted. Read the geometry in chunks: h5py point selection with millions of indices took >10 min where chunked reads take seconds (16×16×16 cell mesh, 10.7M membrane triangles: 14 s on the Vega login node).
  **Runs browser** (`viz/js/app-runs.js`, `viz/run_index.py`, `/api/runs*`): one tree of every run, local and on every cluster, replacing the old results dropdown and compare tree. Folders are **virtual**: a run's folder is a `/`-path in `viz/run_labels.json` (`runs[name].folder`, plus `folders` so empty ones persist; the old one-level `collection` field is migrated on load), so filing/renaming/moving never touches data and every lookup by run name keeps working. Unfiled runs group by mesh. Tick = compare in the charts (remote-only runs' iterations are fetched on demand) and selection for Move/Delete; click = current run for Load/Download/Video. Each cluster is listed with one ssh call (`Cluster.list_remote_runs`: iterations/results/size per folder, plus `squeue`'s working-directory column to spot queued/running jobs, since a pending job's folder has no `slurm_<id>.out` yet). The last good listing is cached in `viz/run_index_cache.json`, so an unreachable cluster (Vega without OTP) shows stale rather than empty. Delete removes a run everywhere (local dir, viz cache, every cluster copy + its `<name>_slurm.log`, label, job-list entry) and skips runs with active jobs. "Failed" = no iterations/results anywhere and no active job. A failed run is kept while its job is in the job list; dismissing the job (or Clear list) deletes it, and "Delete failed" bulk-removes the rest. Every such delete passes `only_if_empty`, re-checked on the cluster itself. The same button removes empty cluster copies of runs that have data elsewhere: these were sync artifacts from when the rsync exclude was `*_sim/`, which missed timestamped run folders (now `*_sim*/`).

### Key invariants when touching mesh / tagging code

- Each volume tag → one FEM space. Neighbouring cells must not share a tag (graph coloring guarantees this for `*_colored.xdmf`).
- Interior-facet integrals require `GhostMode.shared_facet`. Custom partitioners must return multi-destination adjacency (first = owner, rest = ghost ranks).
- After mesh redistribution, vertex global indices on ghost vertices are NOT reliable — use `original_cell_index` (which DOLFINx maintains for local + ghost cells) to reconstruct facet tags via the cell-pair → tag map.

## Docker / containers

Dev image: `ghcr.io/fenics/dolfinx/dolfinx:v0.9.0`. Then `pip install --no-build-isolation -r requirements.txt`. `pymetis` is installed separately by `viz/server.py` to avoid build conflicts. Ginkgo dev image built from `dolfinx-ginkgo/Dockerfile`. Karolina build pitfalls (apptainer `--contain`, `TMPDIR`, env scrubbing, ParMETIS-from-source) are documented in the user memory and `docs/` — consult before changing the build.
